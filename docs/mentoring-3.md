# 3차 멘토링

> **다 찾아드림** · 멀티모달 RAG 기반 지능형 비디오 검색 시스템
>
> 2차 멘토링(2026-10-12) 자문 의견에 대한 보완 보고

---

## 1. 보완 개요

2차 멘토링에서 제시된 의견을 바탕으로 장면 설명을 보강한 뒤 공식 검색 성능을 재평가하고,
멀티모달 신호별 기여도와 비용 대비 효과를 분석하였다. 또한 근거 부족 질문 대응, 장면 병합
방식, 처리 효율을 실험적으로 검토하고, 실제 사용자 평가를 통해 시스템의 활용 가능성을
검증하였다.

**평가 표본** — 영상 18개 · 장면 카드 203개 · 질문 48개(재료·분량 19 / 순서·타이밍 16 /
시각적 상태 13) · 정답 라벨 113줄 · 사용자 평가 참가자 10명(60과제). 질문은 개발팀이 아닌
외부 인원이 작성하였고, 정답 시간 구간은 담당 영상별로 분담해 사람이 직접 판정하였다.

## 2. 주요 자문 의견 및 보완 결과

### ① 공식 기준선 확정

자문 당시 제시한 **0.806** 은 장면 설명이 55%만 채워진 상태에서, 설명이 비어 있는 영상
5개를 제외하고 13개로 측정한 값이다. 이후 저장된 프레임으로 설명을 **81%까지 채우고**
전체 영상 18개를 대상으로 재측정하여 아래 값을 **공식 기준선으로 확정**하였다.

| 조건 | nDCG@5 | Recall@5 | mAP | 1위적중 |
| --- | ---: | ---: | ---: | ---: |
| 음성 단일 기준선 | 0.719 | 0.802 | 0.607 | 0.625 |
| **현행 (음성+자막+설명+이미지)** | **0.745** | **0.802** | **0.621** | **0.688** |
| 개선폭 | +0.027 | ±0 | +0.014 | +0.063 |

질문 유형별로는 재료·분량 0.689, 순서·타이밍 0.688, 시각적 상태 0.899 로, **시각적 상태
질문에서 멀티모달 결합의 이점이 가장 뚜렷**하게 나타났다.

> **채움률 81% 가 상한인 이유** — 외부 API 호출을 영상당 1회로 제한하고 1회 호출에
> 프레임 12장을 묶어 처리하는 구조상, 장면이 12개를 넘는 영상은 전부 채울 수 없다.
> 이론상 최대치가 82%(167/203)이며 실제 81%(165/203)로 사실상 상한에 도달하였다.

### ② 신호별 기여도 — 제거법 15조건 전수 평가

음성·자막·장면 설명·이미지의 **15개 신호 조합을 전수 평가**하였다. 조건마다 색인을 따로
구성하고 제품과 동일한 검색 코드를 호출하였으며, 추가 외부 API 호출은 발생하지 않았다.

| 평가 조건 | nDCG@5 | Recall@5 | mAP | 1위적중 |
| --- | ---: | ---: | ---: | ---: |
| 전체 신호 결합 (기준) | 0.745 | 0.802 | 0.621 | 0.688 |
| **장면 설명 제외** | **0.772** | **0.833** | **0.660** | **0.750** |
| 자막 제외 | 0.765 | 0.781 | 0.630 | 0.708 |
| 음성 제외 | 0.697 | 0.771 | 0.561 | 0.604 |
| 음성 단독 | 0.717 | 0.750 | 0.610 | 0.688 |
| 이미지 단독 | 0.470 | 0.594 | 0.368 | 0.292 |
| *(참고) 무작위 선택* | *0.443* | — | — | — |

> **표 ①의 기준선과 표 ②의 음성 단독은 값이 다르다.** 표 ①은 음성만으로 색인을 새로
> 구성한 공식 조건이고, 표 ②는 전체 색인에서 다른 신호를 제거한 것으로 측정 경로가
> 다르기 때문이다. **비교는 같은 표 안에서만** 유효하다.

**장면 설명 제외 조건이 네 지표 전부에서 더 높았다**(Recall +0.031 · mAP +0.039 ·
1위적중 +0.062). 한 지표만 개선되었다면 지표 선택의 문제일 수 있으나, 네 지표가 같은
방향을 가리키므로 그렇게 보기 어렵다.

| 비교 | 평균차 | 95% 신뢰구간 | 부호검정 | 판정 |
| --- | ---: | --- | ---: | --- |
| **장면 설명 제외** | **+0.026** | [−0.007, +0.061] | **p=0.029** | 방향은 분명(↑19 / ↓7), 크기는 미확정 |
| 자막 제외 | +0.020 | [−0.019, +0.064] | p=0.523 | 구분되지 않음 |
| **음성 제외** | **−0.049** | [−0.132, +0.027] | p=0.585 | **손해가 가장 큼** |
| 이미지 제외 | −0.011 | [−0.043, +0.020] | p=1.000 | 구분되지 않음 |

질문 유형별로 보면 원인이 분명하다.

| 유형 | 장면 설명 제외 시 변화 | 95% 신뢰구간 | n | 판정 |
| --- | ---: | --- | ---: | --- |
| **재료·분량** | **+0.084** | [+0.037, +0.139] | 19 | **통계적으로 유의** |
| 순서·타이밍 | +0.017 | [−0.020, +0.064] | 16 | 구분되지 않음 |
| 시각적 상태 | −0.046 | [−0.117, +0.013] | 13 | 구분되지 않음 |

**재료·분량 질문에서 장면 설명이 성능을 떨어뜨린다는 점만 통계적으로 확실하다.** 분량은
자막에 글자로 표기되어 있는데 생성된 설명이 이를 희석하는 것으로 판단된다. 반대로 시각적
상태에서의 손해는 신뢰구간이 0을 포함하여 확정되지 않았다.

한편 **이미지 단독 검색(0.470)은 무작위 선택(0.443, 2,000회 시행, 95% 범위
[0.366, 0.523]) 범위 안에 들어간다.** 무작위로 골라도 네 번에 한 번꼴(23%)로 이 값을
넘는다. 한 영상 안에서 특정 순간을 찾는 과제에서는 이미지 신호만으로 동작하지 않음을
확인하였다.

### ③ 비용 대비 효과 재검토 — 장면 설명(Gemini)

자문에서 요구한 재검토의 대상은 **"장면 설명 생성을 계속 유지할 것인가"** 이다. 성능과
비용을 분리해 정리하면 다음과 같다.

| 관점 | 측정 결과 | 해석 |
| --- | --- | --- |
| **성능** | 제외 시 네 지표 모두 상승(+0.026 등), 재료·분량에서만 유의 | 유지할 근거가 **없음** |
| **처리 시간** | 자막 OCR과 함께 서버 처리의 81%를 차지 | 유지 비용이 **큼** |
| **처리량** | 유일한 외부 API 호출. 무료 한도상 **하루 20개 영상**이 상한 | 확장의 **병목** |
| **금전 비용** | 0원(무료 한도 내) | 제약은 돈이 아니라 처리량 |

**따라서 현재 측정 범위에서는 장면 설명을 제외하는 편이 유리하다.** 다만 즉시 제거하지
않고 **조건부 유지**를 선택하였으며, 그 이유는 다음과 같다.

> 장면 설명이 기여할 것으로 기대되는 영역은 **시각적 상태 질문**이다. 그런데 해당 유형의
> 질문이 현재 **13개뿐이어서**, "설명을 제거하면 시각적 상태가 나빠진다"는 결과가
> 신뢰구간 안에서 확정되지 않는다(−0.046, [−0.117, +0.013]).
>
> 제품의 핵심 주장이 걸린 유형이므로, **해당 유형 질문을 30개 수준으로 보강한 뒤 다시
> 측정하여 최종 결정**한다. 보강 후에도 손해가 확인되지 않으면 장면 설명을 제거하고
> **전 구간 로컬 모델 구성**으로 전환한다. 이 경우 외부 API 의존이 사라져 하루 처리량
> 제약도 함께 해소된다.

### ④ 답이 없는 질문에 대한 대응

관련 장면이 없는 질문에도 검색 결과가 제공되던 문제를 개선하기 위해, **정규화 이전
유사도** 기반의 근거 부족 경고 기능을 구현하였다. 점수 정규화 후에는 절대적인 확신도가
사라지므로, 정규화 전 코사인 값을 별도로 보존하여 판정에 사용하였다.

운영 임계값은 임의로 정하지 않고 **곡선을 그려 데이터로 선택**하였다.

| 임계값 | 분야가 다른 질문<br>(10건) | 정답 장면이 없는 질문<br>(12건) | 정답이 있는데<br>잘못 경고 | 경고 정확도 |
| :-: | :-: | :-: | :-: | ---: |
| 0.48 | 8 | 2 | 2 | 0.833 |
| 0.50 | 9 | 4 | 4 | 0.765 |
| **0.52** | **10** | **7** | **5** | **0.773** |
| 0.54 | 10 | 9 | 8 | 0.704 |
| 0.56 | 10 | 13 | 13 | 0.594 |

**0.52 를 운영점으로 채택하였다.** 분야가 다른 질문 10건을 모두 걸러내면서 경고 정확도가
유지되는 지점이며, 0.54 이상에서는 잘못된 경고가 급격히 늘어난다.

다만 이 임계값에서도 정답이 있는 질문 5건에서 불필요한 경고가 발생한다. 경고로 결과를
**차단하면** 사용자가 존재하는 장면을 영영 보지 못하게 되지만, **경고만 띄우면** 피해가
"불필요한 안내 한 줄"로 끝난다. 따라서 **결과를 차단하지 않고 경고와 함께 후보 장면을
제공하는 방식**을 채택하였다.

### ⑤ 순서·타이밍 질문의 검색 정확도 개선

4초 고정 분할의 한계를 개선하기 위해 **인접 장면 병합 및 시점 보정 기능**을 구현하고
성능을 비교하였다.

| 분할 방식 | 카드 길이 | 정답을 품은 카드를 가져옴 | 평균 시점 오차 | nDCG@5 |
| --- | ---: | ---: | ---: | ---: |
| **4초 고정 (현행)** | 4.0초 | 65/94 (69%) | **2.8초** | **0.756** |
| 의미 단위 병합 | 5.4초 | **73/94 (78%)** | 3.5초 | 0.685 |

병합하면 **정답 구간을 포함하는 장면을 더 잘 찾아온다**(69% → 78%). 조각나 있던 하나의
행위가 한 장으로 모이기 때문이다. 그러나 카드가 길어진 만큼 **이동 지점이 뒤로 밀려**
평균 시점 오차가 2.8초에서 3.5초로 증가하고, 최종 검색 성능은 오히려 저하되었다.

시점 보정 기능과 이상적 조건(상한 측정)을 추가로 실험했으나 실질적 개선을 확인하지 못해,
**시점 이동의 정확성을 우선하여 4초 고정 분할을 유지**하기로 결정하였다. 구현한 병합
기능은 설정값으로 끈 상태로 코드에 남겨 두었다.

> 개선안을 구현한 뒤 측정 결과에 따라 **채택하지 않기로 결정한 사례**이다. 이 제품의
> 목표가 "맞는 장면을 보여주는 것"이 아니라 "맞는 **초**로 이동시키는 것"이기 때문이다.

### ⑥ 영상 처리 시간 및 비용 분석

영상 18개를 대상으로 저장 과정의 단계별 소요 시간을 실측하였다.

| 구분 | 평균 | 비중 |
| --- | ---: | ---: |
| 영상 길이(= 캡처 시간, 실시간 1배속) | 47.2초 | 30% |
| **서버 처리** | **111.7초** | 70% |
| **사용자 대기 합계** | **158.9초** | 100% |

서버 처리 111.7초의 내부 구성은 다음과 같다.

| 단계 | 평균 | 비중 |
| --- | ---: | ---: |
| 음성 인식 | 13.7초 | 12.3% |
| **프레임 분석 (자막 OCR + 장면 설명)** | **90.8초** | **81.2%** |
| 벡터 생성 | 5.6초 | 5.0% |
| 기타 | 1.6초 | 1.5% |

**서버 처리 시간의 81%가 프레임 분석 단계에 집중**되어 있다. 외부 API 호출은 영상당
4회에서 **1회로 축소**하였으나, 무료 한도(모델당 1일 20회)로 인해 **하루 20개 영상**이
처리량 상한으로 남아 있다. 금전적 지출은 0원이며, **제약은 비용이 아니라 처리량**이다.

이를 통해 **프레임 분석 최적화와 외부 API 의존도 감소**가 향후 서비스 확장의 주요 과제임을
확인하였다. ③에서 장면 설명 제거가 확정되면 이 두 과제가 동시에 해소된다.

### ⑦ 실제 사용자 평가를 통한 활용 가능성 검증

참가자 **10명**을 대상으로 총 **60개 과제**를 수행하여, YouTube 직접 탐색(A)과 제안
시스템 검색(B)의 탐색 효율을 비교하였다.

| 항목 | A 직접 탐색 | **B 제안 시스템** |
| --- | ---: | ---: |
| 평균 소요 시간 | 27.3초 | **9.3초 (66% 단축)** |
| 중앙값 | 27.3초 | 8.5초 |
| 평균 시도 횟수 | 1.56회 | **1.10회** |

**참가자 10명 전원**에서 제안 시스템이 더 빨랐으며(개인별 54%~80% 단축),
**부호검정 결과 p = 0.002 로 통계적으로 유의하다.**

과제 성공률은 다음과 같다.

| 판정 기준 | A | B |
| --- | ---: | ---: |
| 사전에 정한 기준 (정답 시작 −5초 ~ +2초) | 28/30 (93%) | 25/30 (83%) |
| 대안 기준 (정답 구간 전체 −5초 ~ +2초) | 30/30 (100%) | 29/30 (97%) |

**성공률은 양쪽 모두 90% 안팎으로 천장에 가까워 변별력이 없었다.** 사전 기준에서 B가 낮게
나오나, **실패 7건 중 6건은 정답 구간 안에 도달했으나 기준에서 벗어난 경우**였다. 사전
기준은 정답 구간이 짧다는 전제로 설계한 것인데, 과제 선정 시 구간 길이가 6초·11초인 항목
2개가 포함된 것이 원인이다. 사후에 기준을 바꾸지 않고 **두 기준을 모두 보고**한다.

따라서 이번 평가에서 확인된 효과는 **"성공률 향상"이 아니라 "탐색 시간 단축"**이다.

2차 멘토링 이후 검색 성능 평가 체계를 정비하고, 멀티모달 신호별 기여도와 처리 비용, 장면
분할 방식 및 근거 부족 질문 대응을 실험적으로 검증하였다.

| 자문 요구 사항 | 보완 결과 |
| --- | --- |
| 장면 설명 완료 후 공식 기준선 확정 | 채움률 81%(상한 82%) 달성 후 **nDCG@5 0.745 확정** (①) |
| 비용 대비 효과 재검토 | 제외가 유리하나 **조건부 유지** — 시각적 상태 질문 보강 후 확정 (③) |
| 답이 없는 질문 대응 | 임계값 0.52 경고 기능 구현, **운영점을 곡선으로 선택** (④) |
| 순서·타이밍 개선 (단계 단위 병합) | 구현·측정 후 **미채택** — 시점 오차 증가 (⑤) |
| 처리 시간·비용 측정 | 영상당 158.9초, **프레임 분석이 서버의 81%** (⑥) |
| 사용자 평가로 서비스 가능성 제시 | **탐색 시간 66% 단축**, 10명 전원 개선, p=0.002 (⑦) |

특히 각 기술의 실제 효과를 정량적으로 비교하고, **결과에 따라 개선안의 채택 여부를
결정**함으로써 시스템 설계의 타당성을 검토하였다. 병합 기능과 같이 구현 후 미채택한 사례도
그대로 보고하였다. 또한 실제 사용자 평가에서 평균 탐색 시간을 약 66% 단축하여, 저장된
숏폼 콘텐츠의 정보 접근성과 활용성을 높일 수 있는 가능성을 확인하였다.
