**프로젝트 요약** (요약 칸)

> 저장한 유튜브 쇼츠에서 필요한 장면을 다시 찾기 어려운 문제를 해결하기 위해, 영상의 음성·화면 자막·이미지를
> 4초 단위 장면 카드로 색인하고 자연어 질문으로 해당 장면을 찾아 근거와 함께 원본 영상의 그 시점으로 이동시키는
> 크롬 확장 기반 멀티모달 RAG 검색 시스템을 개발하였다. 음성 인식(faster-whisper), 자막 인식(EasyOCR),
> 텍스트 임베딩(BGE-M3), 이미지 임베딩(SigLIP2)을 모두 로컬 모델로 구성하고, 질문 유형별 가중 결합 하이브리드
> 검색을 적용하였다. 외부 인원이 작성한 질문 48개로 평가한 결과 nDCG@5가 음성 단독 기준선 0.717에서 0.772로
> 향상되었고, 사용자 10명(60개 과제) 평가에서 장면 탐색 시간이 27.3초에서 9.3초로 약 66% 단축되었다.

## 1. 과제의 개요

### 가. 배경 및 필요성

1) **숏폼 콘텐츠의 확산과 휘발성 문제.** 쇼츠가 주요 정보 소비 방식으로 확산되면서 요리법·운동 방법 등 생활에
유용한 정보가 짧은 영상으로 압축되어 공유되고 있다. 그러나 핵심 정보가 빠르게 지나가는 특성상 시청 후 필요한
정보를 기억하거나 다시 활용하기 어렵다.

2) **저장 이후 재탐색의 어려움.** 사용자는 유용한 영상을 저장해 두지만, 저장 영상이 많아질수록 원하는 콘텐츠를
다시 찾기 어려워지고, 영상을 찾더라도 필요한 정보가 나오는 구간을 직접 돌려 보며 탐색해야 한다. 플랫폼의 기본
검색은 제목·설명 단위로 동작해 영상 안의 특정 순간을 찾아 주지 못한다.

3) **멀티모달 통합 검색의 필요성.** 쇼츠의 정보는 음성(설명), 화면 자막(재료·분량), 영상 이미지(조리 상태)에
나뉘어 담긴다. 따라서 하나의 신호만으로는 질문에 답하기 어렵고, 여러 정보를 시간 정보와 함께 통합해 이해하고
검색하는 새로운 접근이 필요하다.

### 나. 목표

1) **장면 단위 자연어 검색.** 사용자가 "김치찜 영상에서 양념하는 부분 보여줘"처럼 자연어로 질문하면 저장한
영상들 가운데 관련 장면을 찾아 원본 영상의 해당 시점으로 바로 이동시킨다.

2) **근거 기반 답변.** 검색된 장면의 음성·자막·시간 정보를 근거로 답변을 생성하고, 근거가 부족한 질문에는
경고를 표시하여 신뢰할 수 있는 결과를 제공한다.

3) **정량적 검증.** 외부 인원이 작성한 질문과 사람이 판정한 정답 구간으로 검색 성능(nDCG@5, Recall@5, mAP,
1위 적중률)을 측정하고, 실제 사용자 평가로 탐색 시간 단축 효과를 검증한다.

### 다. 개발 내용

1) **멀티모달 색인 파이프라인.** 크롬 확장이 브라우저에서 재생 중인 영상을 0.5초 간격 프레임과 16kHz 오디오로
수집하고, 서버가 음성 인식·자막 인식·임베딩을 거쳐 4초 단위 장면 카드로 색인한다.

2) **하이브리드 검색 및 근거 기반 RAG.** 텍스트 임베딩·단어 매칭·이미지 임베딩 점수를 질문 유형별 가중치로
결합하여 장면 순위를 정하고, 상위 장면을 근거로 LLM이 구조화된 답변을 생성한다.

3) **크롬 확장 서비스.** 저장 영상 보관함, 자연어 검색 화면, 관련 장면 및 근거 제시, 원본 시점 이동, 사진
레시피 보기와 재료 구매 링크 기능을 제공한다.

## 2. 과제의 내용

### 가. 설계 및 개발의 내용

#### 1) 개념 설계 (구조 설계)

가) **전체 구조.** 시스템은 크롬 확장(클라이언트)과 FastAPI 서버로 구성된다. 크롬 확장은 영상 수집과 사용자
화면을, 서버는 분석·색인·검색·답변 생성을 담당한다. 처리 흐름은 ① 멀티모달 처리(색인) → ② 하이브리드 검색 →
③ 근거 기반 RAG의 세 단계로 나뉜다.

| 단계 | 입력 | 처리 | 출력 |
| --- | --- | --- | --- |
| ① 멀티모달 처리 | 0.5초 간격 프레임, 16kHz 오디오 | 음성 인식 · 자막 인식 · 텍스트/이미지 임베딩 | 4초 장면 카드 (Qdrant 벡터 + SQLite 메타데이터) |
| ② 하이브리드 검색 | 자연어 질문 | 코사인 유사도 · 단어 매칭 · 유형별 가중 결합 | 영상 목록 · 장면 순위 |
| ③ 근거 기반 RAG | 상위 장면의 말 · 자막 · 시간 | LLM 근거 기반 답변 생성 | 구조화된 답변 + 원본 시점 이동 |

나) **설계 원칙.**
- **서버는 유튜브에 접속하지 않는다.** 영상 파일을 내려받지 않고, 사용자의 브라우저에서 재생 중인 화면과
  소리를 확장이 수집해 올린다. 재생은 항상 유튜브에서 일어나며 검색 결과는 해당 시점으로 이동시키는 방식이다.
- **모델 단계마다 교체 가능한 인터페이스.** 각 단계를 외부 API와 로컬 모델이 같은 인터페이스로 구현하여 설정
  한 줄로 전환하고, 같은 코드 경로로 비교 실험을 수행할 수 있게 하였다.
- **사용자 격리.** 모든 조회·검색·삭제에 사용자 식별자 필터를 강제하고 자동 테스트로 검증한다.

#### 2) 상세 설계 (기능 설계)

가) **멀티모달 처리(색인).**

| 기능 | 모델 | 설명 |
| --- | --- | --- |
| 음성 받아적기 | faster-whisper (small) | 단어 단위 시간 포함 전사 |
| 화면 자막 읽기 | EasyOCR | 한국어 + 영어, 전 프레임 |
| 텍스트 임베딩 | BGE-M3 (1024차원) | 음성·자막 텍스트의 의미 벡터 |
| 이미지 임베딩 | SigLIP2 | 장면 대표 프레임의 이미지 벡터 |
| 저장소 | Qdrant / SQLite | 텍스트·이미지 벡터 2종 / 장면 카드·요약 |

장면 카드는 `{장면 번호, 시작·종료 시각, 음성, 자막, 장면 설명, 대표 프레임}` 의 고정된 형태로 저장한다. 색인
단계의 모든 모델을 로컬에서 실행하여 외부 API 비용과 호출 한도에 따른 처리량 제약을 없앴다.

나) **하이브리드 검색.**
- 질문을 BGE-M3와 SigLIP2 텍스트 인코더로 각각 벡터화하고, 코사인 유사도로 상위 40개 후보를 고른다.
- 후보 텍스트에 질문의 단어가 포함되는지를 IDF 가중으로 계산하는 단어 매칭 점수를 더한다.
- 질문 유형(의미 / 단어 / 이미지)에 따라 신호별 가중치를 달리하여 결합한다:
  `S = w₁·S_음성 + w₂·S_자막 + w₃·S_이미지` (w: 질문 유형별 가중치)
- **SigLIP2 질의 최적화.** SigLIP2는 영어 중심으로 학습되어 있으므로 질문을 영어로 번역하고,
  `a photo of {query}` 형태의 프롬프트 템플릿과 소문자화를 적용한다. 번역 결과는 캐싱하여 같은 질문에 항상 같은
  결과를 내도록 하였다.

다) **근거 기반 RAG 및 근거 부족 경고.**
- 상위 장면의 말·자막·시간을 근거 컨텍스트로 구성하여 Gemini 3.5 Flash-Lite가 요리 단계·레시피 형태의 구조화된
  답변을 생성한다. 답변에는 근거가 된 시각(예: 52.0~60.0초)을 함께 표시한다.
- 점수를 정규화하면 1위가 항상 만점이 되어 확신도를 나타낼 수 없으므로, 정규화 이전 코사인 유사도를 별도로
  보존하여 임계값(0.52) 미만이면 "근거 부족" 경고를 표시한다. 결과를 차단하지 않고 경고와 함께 후보 장면을
  제공한다.

#### 3) 개발의 내용

가) **서버(FastAPI).** 영상 업로드 수신, 작업 큐, 단계별 분석 상태 기록, 실패 등급 구분, 로컬 모델 동시 실행
제어(16GB 메모리 환경), 검색·답변 API를 구현하였다. 조용히 빈 결과를 내던 분석 오류 16건을 찾아 수정하고,
실패가 화면에 드러나도록 구조를 바꾸었다.

나) **크롬 확장.** 저장 영상 보관함, 자연어 검색 화면(영상 목록 + 장면 드롭다운), 관련 장면 및 근거 표시,
원본 시점 이동, 사진 레시피 보기(번호 배지 + 스틸컷 + 단계 설명), 재료 구매 링크를 구현하였다. 저장 작업을
별도 창으로 분리하여 저장 중에도 다른 영상을 시청할 수 있게 하였다.

다) **평가 도구.** 신호 조합별 비교 실험 러너, 검색 성능 측정, 신호별 기여도 제거법, 거절 임계값 곡선, 처리
시간·비용 측정, 사용자 평가 집계 스크립트를 구현하였다.

### 다. 최종 결과물

1) **멀티모달 RAG 기반 비디오 검색 시스템 (크롬 확장 + FastAPI 서버).**
- ① 저장 영상 보관함 ② 자연어 검색 ③ 관련 장면 및 근거 제시 ④ 레시피·시점 이동의 네 화면으로 구성된다.
- 예: "김치찜 영상 안에서 양념하는 부분 보여줘" → 0:52 「양념 재료 넣기」 장면을 음성·자막
  근거와 함께 제시하고 원본 영상의 52초로 이동한다.

2) **검색 성능 (외부 작성 질문 48개, 영상 18개 · 장면 카드 203개).**

| 평가 조건 | nDCG@5 | Recall@5 | mAP | 1위 적중 |
| --- | --- | --- | --- | --- |
| 음성 단독 (기준선) | 0.717 | 0.750 | 0.610 | 68.8% |
| **최종 구성 (음성·자막·이미지)** | **0.772** | **0.833** | **0.660** | **75.0%** |

- 음성·자막·장면 설명·이미지 네 신호의 15개 조합을 전수 평가하였다. 장면 설명(외부 API)을 제외한 구성이 네
  지표 모두에서 가장 높았고, 장면 설명은 재료·분량 질문에서 성능을 유의하게 떨어뜨렸다(제외 시 +0.084, 95%
  신뢰구간 +0.037~+0.139). 이에 따라 장면 설명을 제외한 구성을 최종 구성으로 채택하였다.
- 음성 단독 대비 최종 구성의 개선은 nDCG@5(+0.055, 95% 신뢰구간 +0.005~+0.109)와 Recall@5(+0.083,
  +0.031~+0.135)에서 통계적으로 확인되었다.
- 신호별 기여(nDCG@5): 자막 제외 0.765, 이미지 제외 0.734, 음성 제외 0.697, 이미지 단독 0.470. 음성이 가장 큰
  기여를 하며, 이미지 단독은 같은 영상 안 무작위 선택(0.443)과 구별되지 않아 보조 신호로 쓰인다.

3) **사용자 평가 (참가자 10명, 60개 과제).**

| 항목 | YouTube 직접 탐색 | 제안 시스템 |
| --- | --- | --- |
| 평균 탐색 시간 | 27.3초 | **9.3초 (약 66% 단축)** |
| 중앙값 | 27.3초 | 8.5초 |
| 평균 시도 횟수 | 1.56회 | 1.10회 |
| 과제 성공률 (사전 기준) | 93% (28/30) | 83% (25/30) |

- 참가자 10명 전원에서 탐색 시간이 줄었다(부호검정 p = 0.002). 성공률은 두 방식 모두 90% 안팎으로 높아 차이를
  가리기 어려웠으며, 실패 7건 중 6건은 정답 구간 안에 도달했으나 사전 기준(정답 시작 −5초~+2초)을 벗어난
  경우였다. 확인된 효과는 탐색 시간 단축이다.

4) **설계 검증 실험.**
- **근거 부족 경고:** 임계값 0.52에서 분야가 다른 질문 10건 모두, 정답 장면이 없는 질문 12건 중 7건에 경고가
  표시되었고, 정답이 있는 질문 48건 중 5건에서 불필요한 경고가 발생하였다.
- **장면 병합:** 인접 장면 병합 시 정답 포함 장면 검색률은 69%→78%로 올랐으나 평균 시점 오차가 2.8초→3.5초로
  늘어 4초 고정 분할을 유지하였다.
- **SigLIP2 파인튜닝:** LoRA·선형 정렬 두 방식을 실험했으나 실제 한국어 쇼츠 데이터에서 이득이 없어 채택하지
  않았고, 질의 영어 번역 등 전처리만 적용하였다.
- **처리 시간:** 영상당 평균 158.9초(캡처 47.2초 + 서버 111.7초)이며 서버 처리의 81%가 프레임 분석 단계였다.

### 마. 개선 방안

1) **프레임 분석 단계 최적화.** 영상 1개 저장에 평균 158.9초가 걸리며, 서버 처리 시간(111.7초)의 81%가 프레임
분석(자막 인식) 단계에 집중되어 있다. 최종 구성에서 장면 설명이 빠져 외부 API 호출과 하루 처리량 제약은
해소되었으므로, 남은 병목은 0.5초 간격 전 프레임에 수행하는 자막 인식이다. 연속 프레임 간 화면 변화가 작으면
인식을 건너뛰거나 자막 영역만 인식하는 방식으로 처리 시간을 줄일 수 있다.

2) **자체 평가.** 각 기술의 효과를 같은 평가셋과 같은 코드 경로로 정량 비교하고, 측정 결과에 따라 개선안의
채택 여부(장면 설명 제외, 장면 병합 미채택, 파인튜닝 미채택)를 결정하였다. 다만 최종 구성은 15개 조합 중 같은
평가셋에서 가장 높은 조합을 고른 것이어서 수치가 다소 낙관적일 수 있다.

## 3. 과제의 향후 계획

### 가. 활용 방안

1) **개인 숏폼 지식 보관함.** 요리·운동·DIY·학습 등 정보성 쇼츠를 저장해 두고, 필요한 순간 자연어로 해당 장면을
바로 찾아보는 개인용 도구로 활용할 수 있다. 사진 레시피 보기와 재료 구매 링크처럼 검색 결과를 실제 행동으로
연결하는 기능으로 확장할 수 있다.

2) **영상 플랫폼의 장면 단위 검색 기술.** 음성·자막·이미지를 시간 정보와 함께 색인하는 구조는 쇼츠에 국한되지
않으므로 강의 영상, 사내 교육 영상, IPTV·VOD 등 긴 영상의 장면 검색과 하이라이트 탐색에 적용할 수 있다.
색인 단계가 모두 로컬 모델로 구성되어 있어 외부 전송이 어려운 환경에도 적용 가능하다.

3) **서비스화 시 유의 사항.** 현재 시스템은 개인 학습·연구 목적이며, 외부 플랫폼 콘텐츠를 가공·보관하므로
서비스화한다면 해당 플랫폼 이용약관 검토가 선행되어야 한다.

### 나. 기대 효과

1) **정보 탐색 시간 단축.** 사용자 평가에서 확인된 것처럼 영상을 처음부터 돌려 보는 대신 질문 한 번으로 필요한
장면에 도달하여 탐색 시간을 약 66% 줄일 수 있다.

2) **저장 콘텐츠의 재활용성 향상.** 저장만 하고 잊히던 숏폼 콘텐츠를 다시 검색하고 실질적으로 활용할 수 있는
정보 자산으로 바꾼다.

3) **신뢰할 수 있는 검색 결과.** 답변마다 근거 장면과 시각을 함께 제시하고 근거가 약하면 경고하므로, 사용자가
결과를 원본에서 직접 확인할 수 있다.

4) **낮은 운영 비용.** 색인 단계를 로컬 모델로 구성하여 영상 수가 늘어도 외부 API 비용과 호출 한도에 묶이지
않는다.
